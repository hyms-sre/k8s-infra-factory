# 自测清单与验收

> 用法：每个阶段结束后做对应小节的自测；全部走完后做最后的整体验收。
> **不要自欺** —— 说不清就是没掌握，回去补。

## 阶段 1 — 环境与 IaC 基础

- [ ] 能画出 `cluster.yaml → generate.py → vm.tf → terraform apply → VM` 的数据流
- [ ] 知道 `vm.tf` 是生成物，改配置要改 `cluster.yaml`
- [ ] 能解释 `plan` 里 `+` / `~` / `-` 的含义
- [ ] 能说出 `for_each` 比 `count` 好在哪（提示：删中间一台会怎样）
- [ ] 改错 IP 后能预测出会触发重建，并解释原因

**自测题**：把 `workers` 从 3 改成 5，说明需要执行哪几步、`plan` 会显示什么。

## 阶段 2 — 主机初始化与 Cloud-Init

- [ ] 能说出 Cloud-Init 的 datasource 在本项目里是什么
- [ ] 能区分 `meta-data` 和 `user-data` 各管什么
- [ ] 新 VM 上 `cloud-init status` 是 `done`
- [ ] `containerd` active、`kubeadm version` 有输出
- [ ] swap 已关、`overlay` / `br_netfilter` 已加载
- [ ] 能解释**为什么不在 Cloud-Init 里 `kubeadm init`**

**自测题**：节点起来后 `containerd` 没跑，你会按什么顺序排查？

## 阶段 3 — kubeadm 集群引导

- [ ] 能说出 `kubeadm init` 的 5 个主要动作
- [ ] 理解控制面是**静态 Pod**
- [ ] 知道 `NotReady` 通常只是缺 CNI
- [ ] 能自己生成 join 命令并成功加入 worker
- [ ] 能干净地 `kubeadm reset` 后重新引导
- [ ] 能说出改 K8s 版本会联动哪些东西

**自测题**：`kubectl get nodes` 显示 NotReady，你的第一步是什么？（不是 reset）

## 阶段 4 — CN 网络与镜像仓库

- [ ] 能说出 DNS 污染和镜像拉不动是**两个**独立问题
- [ ] OpenWrt 能正确解析本地域
- [ ] Harbor proxy 项目绑定正确
- [ ] 第二次拉同一镜像明显更快、Harbor 存储增长
- [ ] `journalctl -u containerd | grep host=` 无直连上游失败
- [ ] 能解释 `config_path` 多路径为什么导致"配了不生效"

**自测题**：`crictl pull` 超时，报错里是 `registry-1.docker.io` 的 IP。问题在 DNS、Harbor、还是节点 certs.d？

## 阶段 5 — 平台插件与能力扩展

- [ ] 所有节点 `Ready`
- [ ] 能说出为什么 CNI 必须最先装
- [ ] 有 `LoadBalancer` 拿到外部 IP
- [ ] `HTTPRoute` 转发正常
- [ ] PVC 能 `Bound`
- [ ] 面板可访问

**自测题**：Gateway 一直没有外部 IP，按可能性排序你的排查步骤。

## 阶段 6 — 生产化与运维

- [ ] 有一条**验证过会响**的告警
- [ ] 能说出 SLI / SLO / Error Budget 的关系
- [ ] 有生效的 Kyverno 策略
- [ ] GitOps 能纠正手动漂移
- [ ] **完整演练过销毁重建**，记录了耗时
- [ ] 说得清数据备份位置与恢复方式

**自测题**：集群整个挂了，从零恢复到业务可用需要几步？每步大概多久？

## 最终验收标准

能独立完成下面这条**端到端闭环**，说明你已掌握本项目：

```
1. 改 cluster.yaml（改节点数 / 规格 / K8s 版本任一项）
2. terraform apply  → VM 建出来
3. 确认节点到达 kubeadm-ready（cloud-init done / containerd active）
4. 引导集群（init + join）
5. 装 CNI → 节点 Ready
6. （cn 环境）确认镜像走 Harbor 缓存
7. 装入口（MetalLB + Gateway API）→ 有外部 IP
8. 装存储（Longhorn）→ PVC Bound
9. 部署一个应用 → 通过外部 IP 访问成功
10. terraform destroy 全销毁
11. 重复 2–9 一次，成功
```

**第 10–11 步是关键**：能**反复销毁重建**，才说明这套 IaC 真的被你掌握了。

## 故障排查能力自测

不看文档，独立排查以下故障（可故意制造）：

| 故障 | 你要能定位到 |
|---|---|
| 节点 NotReady | 是缺 CNI 还是 kubelet/运行时问题 |
| 镜像拉不动 | 是 DNS、Harbor、还是节点 certs.d |
| Pod Pending | 是资源不足、污点、还是调度约束 |
| LoadBalancer Pending | 是没装 MetalLB 还是地址池耗尽 |
| PVC Pending | 是没装 CSI 还是 StorageClass 缺失 |
| 集群起不来 | 静态 Pod 日志、证书、etcd 状态 |
