# 阶段 6 — 生产化与运维

> 这一阶段是**可选的**：只搭实验环境可以跳过。目标是把"能跑的集群"变成"能运营的集群"。

## 前置条件

- 阶段 5 检查点通过（集群能力完整）
- 已有 `live/prod/` 的目标环境概念

## 学习目标

1. 集群出问题时，怎么在**用户发现之前**知道？
2. 怎么保证集群里跑的镜像"是审查过的"？
3. 变更怎么做到**可追溯、可回滚**？
4. 集群整个挂了，怎么重建？数据怎么办？

## 核心概念

### 1. 从"能跑"到"能运营"的四个维度

| 维度 | 问题 | 对应分类 |
|---|---|---|
| **可观测** | 出问题我怎么知道 | [04-可观测性](../04-可观测性/index.md) |
| **安全** | 怎么保证镜像/配置是可信的 | [06-安全](../06-安全/index.md) |
| **交付** | 变更怎么可追溯可回滚 | [05-GitOps](../05-GitOps/index.md) |
| **可靠** | 挂了怎么恢复 | [11-SRE](../11-SRE/index.md) |

### 2. 可观测的三个信号

| 信号 | 用途 | 本项目选型 |
|---|---|---|
| **Metrics** | 趋势、容量、告警 | Prometheus + Grafana + Metrics Server |
| **Logs** | 定位具体错误 | Loki |
| **（Traces）** | 跨服务链路 | 视需要引入 |

**SLI / SLO / Error Budget**：不要追求"100% 可用"，
而是先定义"什么叫够用"（SLO），再用 Error Budget 决定"还能不能发版"。

### 3. 安全的三道关

| 关卡 | 手段 |
|---|---|
| **镜像可信** | Trivy 扫描、来源限定 |
| **策略约束** | Kyverno（禁止特权容器、强制标签等） |
| **身份与权限** | RBAC、cert-manager 管证书 |

### 4. GitOps 的核心

**集群状态 = Git 仓库状态**。

- 变更走 PR，有 review、有历史、可回滚
- 集群漂移能被检测并纠正
- 谁改的、什么时候改的，全在 Git 历史里

### 5. 备份与演练

> **没演练过的备份等于没有备份。**

必须能回答：集群整个挂了，多久能重建？数据怎么恢复？
本项目因为"全部声明式"，重建路径是清晰的 —— 但**要真的演练一次**。

## 动手实验

### 实验 1：让告警真的响一次

1. 部署监控栈
2. 定义一条简单告警（如"节点 NotReady 持续 1 分钟"）
3. **故意把某个节点弄 NotReady**，确认告警触发
4. 恢复

> 没验证过的告警规则，等于没有。

### 实验 2：加一道策略

用 Kyverno 加一条策略，例如"禁止 `latest` 标签"或"必须设置 resource limits"，
然后提交一个违反策略的 Pod，确认被拒绝。

### 实验 3：用 GitOps 交付

把某个插件的配置放进 Git，用 ArgoCD/Flux 同步。
然后**手动改集群里的资源**，观察 GitOps 是否把它纠正回来。

### 实验 4（最重要）：灾备演练

```bash
# 记录当前状态
kubectl get nodes,pods -A

# 模拟灾难: 销毁全部节点
cd terraform/vsphere && terraform destroy

# 重建
terraform apply
# → 重新引导集群 → 恢复插件 → 恢复数据
```

记录**实际耗时**。这个数字就是你的 RTO（恢复时间目标）。

## 检查点

- [ ] 有一条**验证过会响**的告警
- [ ] 能说出 SLI / SLO / Error Budget 的关系
- [ ] 至少有一条生效的 Kyverno 策略
- [ ] GitOps 能检测并纠正手动漂移
- [ ] **完整演练过一次销毁重建**，并记录了耗时
- [ ] 能说清数据备份在哪、怎么恢复

## 常见坑

| 坑 | 现象 | 原因 / 解法 |
|---|---|---|
| 只配监控不验告警 | 真出事时没收到通知 | 主动触发验证 |
| 告警太吵 | 没人看 | 收敛阈值，只留可行动的 |
| 策略一上来就 `enforce` | 挡住正常业务 | 先用 `audit` 模式观察 |
| GitOps 与手工改冲突 | 改动被反复覆盖 | 一切变更走 Git |
| 备份没演练 | 真恢复时发现不可用 | 定期演练 |
| 单点控制面 | 挂了没法操作 | 生产用多控制面 |
