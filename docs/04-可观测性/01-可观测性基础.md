# 可观测性基础

## 三大支柱

| 支柱 | 回答的问题 | 典型系统 |
|---|---|---|
| Metrics（指标） | 系统状态"如何"（数值时序） | Prometheus / VictoriaMetrics |
| Logs（日志） | 发生了"什么"（离散事件全文） | Loki / ELK / VictoriaLogs |
| Tracing（链路） | 一次请求"经过哪里、耗时在哪" | Tempo / Jaeger / OTel |

## 关键指标分层

- **基础设施**：节点 CPU/内存/磁盘/网络（node-exporter）
- **容器/编排**：Pod 状态/重启/资源（kube-state-metrics + cAdvisor）
- **应用**：RED 方法（Rate 错误率 Duration）；队列类看 USE 方法（Utilization Saturation Errors）
- **业务**：订单量/成功率等（自定义指标）

## Alerting

告警三原则：**可行动**（收到知道做什么）、**有分级**（page/ticket/仅记录）、
**去重聚合**（避免告警风暴）。SLO 驱动的告警（burn rate）优于静态阈值——见 docs/11-SRE。

## K8s 的可观测入口

- kube-state-metrics：对象状态→指标（deploy 副本、pod phase…）
- cAdvisor / kubelet：容器资源指标
- 事件：`kubectl get events` 可接告警（k8s-event-logger）
