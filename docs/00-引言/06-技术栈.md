# 技术栈

> 本文是 **iac-k8s-esxi 技术栈的唯一权威表述**。其它文档提到选型时，以本表为准；
> 版本真值源见 [99-参考/04-版本矩阵](../99-参考/04-版本矩阵.md)。

## 一句话定位

iac-k8s-esxi = **Kubernetes Environment Generator + Terraform IaC**。
以 VMware vSphere 为唯一正式支持的平台，用 `Terraform + Python + Cloud-Init + kubeadm`
把 Kubernetes 环境从 0 声明式地建起来，并且**可以反复销毁重建**。

## 分层选型

| 层 | 选型 | 版本 | 在本项目里的职责 | 仓库位置 |
|---|---|---|---|---|

## 两条部署主线

同一个代码库，用 `live/` 下的不同环境表达两种目标：

| 环境 | 路径 | 网络前提 | 镜像来源 |
|---|---|---|---|
| **default** | `live/lab/vsphere/default/` | 可直连公网 | 上游 registry 直连 |
| **cn** | `live/lab/vsphere/cn/` | 国内受限网络 | OpenWrt 出口 + Harbor 代理缓存 |
| **prod** | `live/prod/vsphere/` | 按需 | 按需 |

> `cn` 不是"另一个版本"，只是同一套 Terraform + Cloud-Init 换了出口与镜像来源。
> 这也是本项目"换环境不改代码"的体现。

## 仓库结构（与技术栈的对应关系）

```
terraform/
  vsphere/        ← 唯一正式支持的平台实现 (cluster.yaml / generate.py / *.tf / *.tpl)
  aliyun/ aws/    ← 预留，仅有 README 设计说明
k8s-plugins/      ← 集群能力扩展，按领域分目录
  networking/ observability/ storage/ security/ platform/ cicd/ gitops/
live/             ← 环境实例 (lab/prod × 平台 × 网络方案)
docs/             ← 知识库正文 (本站内容源)
website/          ← Docusaurus 站点 (本站本体)
scripts/          ← 辅助脚本，按平台分 linux/ macos/ windows/
downloads/        ← 预下载工件缓存 (离线安装用)
secrets/          ← 凭据 (不入 Git)
```

## 版本策略

1. **一次升一层**：平台工具 → K8s 小版本 → 插件大版本，每层跑完整验证。
2. **生产变更前先在 `live/lab` 复刻验证**。
3. **K8s 版本联动**：`generate.py` 的 `K8S_CATALOG` 是唯一真值源，
   由它派生 pause 镜像 / crictl 版本，避免版本号散落各处。
4. **新版本先观望**：刚 GA 的小版本（如 1.37 仅到 `.0`）暂不设为默认，
   等生态（CNI / CSI / Gateway API）跟上再切。

## 明确不包含

避免误解，以下**不是**本项目的技术栈：

- ❌ 大型 Terraform Framework / Terragrunt
- ❌ Python 运维平台或 Web 服务（Python 只做 `cluster.yaml → vm.tf` 的生成器）
- ❌ Kubernetes Operator 开发
- ❌ Shell 脚本集合（声明式优先，脚本只做辅助）
- ❌ 多云统一抽象（vSphere 是唯一正式支持，aliyun/aws 仅预留）
