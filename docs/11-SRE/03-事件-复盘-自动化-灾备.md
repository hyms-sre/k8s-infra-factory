# 事件管理 / 复盘 / 自动化 / 灾备

## Incident Management

- **分级**：P1（服务不可用）→ 立即响应；P2（降级）→ 工作时间；P3 → 排期
- **角色**：Incident Commander（指挥，不亲手修）+ Ops（动手）+ Comms（通报）
- **流程**：发现（告警/用户）→ 定级 → 止血优先（回滚/降级/扩容，先恢复再查因）
  → 恢复宣告 → 复盘
- **沟通**：固定节奏通报（如每 30min），写清"现象/影响/下一步"，不猜原因

## Postmortem（无责复盘）

模板四段：**时间线 → 影响 → 根因（5 Why）→ 行动项**。

铁律：
- 追系统问题不追个人（"谁的错"会让下次隐瞒事故）
- 每个行动项有 owner + 截止日，且**大部分应是自动化/流程修复**而非"加强注意"
- 复盘文档入库，与 Runbook 联动（同样的事故第二次要有现成手册）

## Automation（自动化分级）

1. **可观测自动化**：告警自动关联 Runbook 链接
2. **低危自愈**：磁盘清理、重启卡死 Pod（有上限/有熔断）
3. **平台自动化**：扩容 = 改 cluster.yaml → generate → apply（本项目已具备）
4. **AI 辅助**：docs/10-AI-Ops 的只读诊断 → 逐步授权

自动化纪律：每次自动化一个 Runbook，先演练后上线，失败自动回退人工。

## Disaster Recovery（灾备）

- RTO/RPO 目标先行（业务定，技术实现兜底）
- 本项目可实现的 DR 形态：
  - 集群级：live/lab 从零复刻（cluster.yaml → apply）+ etcd/Velero 恢复（docs/07-存储/05）
  - 数据级：Longhorn backup → 异地 MinIO；数据库逻辑备份双目标
- **演练季度化**：DR 不演练 = 没有 DR；演练记录进 docs/archive 同级的运维记录
