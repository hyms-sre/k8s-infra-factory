# 可靠性与容量

## Reliability（可靠性设计）

- **冗余**：控制面 3 master、存储副本（Longhorn replicas≥2）、应用多副本反亲和
- **失效域隔离**：节点/可用区/依赖分离；一台节点坏 ≠ 服务不可用（靠 PDB 保底）
- **优雅降级**：依赖挂了要"降级可用"（缓存兜底/只读模式），不是跟着挂
- **过载保护**：限流、熔断、负载 shedding——过载时牺牲部分保整体
- **混沌演练**：定期 kill 节点/断网验证自愈（小环境手动模拟即可）

## Capacity（容量规划）

```
容量 = 当前用量 + 增长 + 余量(30%)
```

步骤：

1. **测量**：node-exporter 汇总集群 allocatable vs requests 总和（Prometheus 记录规则）
2. **建模**：按 Pod requests 汇总（不是 limits！）对比节点容量
3. **预警**：集群用量 >70% 触发扩容评审
4. **扩容动作**（本项目的两种路径）：
   - 加节点：cluster.yaml workers.count+1 → generate → apply（新 VM 自助加入）
   - 升规格：cpu/memory 调整 → 原地更新或重建

## 存储容量单独管理

- Longhorn：可用空间 = Σ节点数据盘 × (1/副本数)；预留 20% 快照空间
- 对象存储（MinIO）：生命周期策略 + 定期清理
- 镜像仓库（Harbor）：保留策略防无限增长

## 与 SLO 联动

容量不足通常表现为延迟 SLO 先破——预算消耗分析里"容量型事故"单独归类，
推动季度容量评审常态化。
