# 场景: CN 网络环境（OpenWrt + Harbor + Kubernetes）

## 问题

国内网络直连 Ubuntu apt / pkgs.k8s.io / docker.io / quay.io 不稳定或不可达。

## 方案架构

```
Internet → OpenWrt (出口/DNS/NAT/代理 OpenClash) → Harbor (Registry/Proxy Cache)
        → Kubernetes (containerd certs.d 优先走 Harbor)
```

三段相互独立，推荐部署顺序 OpenWrt → Harbor → K8s；K8s 不硬依赖前两者。

## 1. OpenWrt（examples/openwrt）

- make-vmdk.sh 制作镜像 → 模板 → terraform 克隆 → files/configure.sh 配 LAN/关 DHCP
- dnsmasq-full + 本地域解析（`/harbor.example.local/<ip>`，先 del_list 再 add_list 防重复）
- OpenClash 出口分流（国内直连、海外代理）；开启转发供 Harbor 回源

## 2. Harbor（examples/harbor）

- terraform 建 VM（cloud-init: 数据盘/Docker/域名）→ 手工 install.sh --with-trivy
- HTTPS：内网 CA + 服务器证书 → prepare → 节点分发 CA（update-ca-certificates）
- Proxy Cache 项目（API 建项目必须带 registry_id）：项目名与 cluster.yaml 的
  `harbor.upstreams` 一致；上游选择原则——直连可达用官方、被墙换国内中转
  （docker.1ms.run / *.m.daocloud.io），让 Harbor 回源不依赖代理

## 3. Kubernetes

- `live/lab/vsphere/cn/cluster/cluster.yaml.example` → terraform/vsphere/cluster.yaml
  （aliyun apt 源/pause 镜像/azure helm 源/harbor 启用）
- generate → apply 后节点 certs.d 自动生成 6 个上游映射（write_files，幂等）
- kubeadm init 用 `--image-repository=registry.aliyuncs.com/google_containers`

## 4. 验证清单

```bash
nslookup harbor.example.local <openwrt-ip>          # DNS 解析
curl -s https://harbor.example.local/v2/ -o /dev/null -w '%{http_code}\n'   # 401
crictl pull docker.io/library/busybox:1.36          # 节点透明走 Harbor
journalctl -u containerd | grep host=               # 确认命中 Harbor 而非上游
```

## 排障

| 现象 | 处理 |
|---|---|
| 拉取 404→超时 | 项目名与 certs.d 路径段不一致 |
| nerdctl 正常但 crictl 超时 | containerd config_path 多路径导致 certs.d 被忽略（单一路径!） |
| 证书不受信 | CA 未分发/未 update-ca-certificates |
| DNS 解析不到 | uci address 记录 + dnsmasq restart + 节点 DNS 指向 OpenWrt |
