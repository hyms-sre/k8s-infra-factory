# 平台组成 / 多租户 / 环境管理

## 平台组成（各层的"产品化"要点）

| 平台 | 组成 | 产品化要点 |
|---|---|---|
| K8s Platform | 集群/节点池/准入基线 | cluster.yaml 供给、Kyverno 基线、扩容自动化 |
| CI/CD Platform | Runner/模板/凭据 | 共享流水线模板、构建缓存、凭据托管 |
| GitOps Platform | ArgoCD/Flux + 仓库结构 | App of Apps 脚手架、环境晋升流程 |
| Observability Platform | Prom/Loki/Grafana | 统一 agent 接入、应用 dashboard 模板 |

## Multi-Tenancy（多租户）谱系

| 模式 | 隔离单位 | 成本 | 适合 |
|---|---|---|---|
| Namespace 级 | ns + ResourceQuota + NetworkPolicy | 低 | 团队少、互信高 |
| 集群共享 + vcluster | 虚拟集群 | 中 | 需要独立控制面观感 |
| 集群级 | 每 team/env 一集群 | 高 | 强合规隔离 |

Namespace 级起步清单：ResourceQuota + LimitRange、默认 NetworkPolicy（Kyverno generate）、
RBAC 按组绑定、Pod Security label。

## 环境管理

- 环境数量收敛：dev / staging / prod 三级足够；配置差异用 overlays（不 copy 粘贴）
- **晋升而非复制**：同一 manifest 逐环境晋升（GitOps 目录推进 + 审批）
- 本项目形态：`live/<env>/...` + cluster.yaml 变体 = 基础设施环境；
  GitOps overlays = 应用环境

## 成本与容量

- 节点规格规划按 requests 汇总 + 30% 余量（docs/02-Kubernetes/05）
- 实验环境用 make destroy 复位省资源；prod 不允许 destroy 式操作
