# 平台工程概念

## Platform Engineering 是什么

把"研发自服务所需的全部平台能力"当作**产品**来建设运营：内部客户是开发者，
目标是用平台化方式替代"每个团队重复造基础设施"。

与 DevOps 的关系：DevOps 是文化与方法，Platform Engineering 是其规模化落地的
工程形态——平台团队封装运维复杂性，业务团队专注交付。

## IDP (Internal Developer Platform)

由多个子系统组成的整体：K8s 运行时 + CI/CD + GitOps + 可观测 + 凭据/权限 + 脚手架。
**IDP ≠ 一个 UI**，Portal（如 Backstage）只是门面。

## Golden Path（黄金路径）

为最常见场景提供"默认正确"的模板：新服务 = 一条命令/一个模板，自动获得
流水线、部署清单、监控面板、告警、日志。要点：

- 路径内顺畅（不问问题、不填坑）；路径外仍可行（避免平台变成约束牢笼）
- 模板进 Git，随平台演进升级

## Developer Experience (DX)

度量与改进开发者的"上手时间/部署耗时/排障时长"：

- 上手：clone → 首次部署 < 半天（Golden Path 保障）
- 部署：合并即部署（GitOps），无需找平台团队
- 排障：一条 URL 到日志/指标/trace（可观测平台保障）
