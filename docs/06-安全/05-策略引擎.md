# 策略引擎 (Kyverno / OPA)

## 为什么需要

人工 review 挡不住："谁又用 latest 镜像了""哪个 Deployment 没打 resource limits"。
策略引擎把规范变成集群强制执行的代码。

## Kyverno（推荐起步）

K8s 原生 YAML 写策略，三类规则：

```yaml
kind: ClusterPolicy
spec:
  validationFailureAction: Enforce      # Audit(只报) / Enforce(拦截)
  rules:
  - name: require-limits
    match: {resources: {kinds: [Pod]}}
    validate:
      message: "必须设置 resources.limits"
      pattern:
        spec:
          containers:
          - resources: {limits: {cpu: "?*", memory: "?*"}}
```

- **validate**：校验（必须打 label、必须非 root、镜像必须来自 Harbor）
- **mutate**：自动变更（默认加 sidecar、注入 label）
- **generate**：自动生成资源（每 namespace 生成默认 NetworkPolicy/Secret）

## OPA Gatekeeper

Rego 语言写约束（ConstraintTemplate + Constraint）。更强表达力、Rego 学习成本高，
适合平台团队统一治理多集群。

## 起步策略集

1. 禁止 latest 镜像标签
2. 必须设置 resources requests/limits
3. 镜像必须来自内部 registry（Harbor）
4. 生产 namespace 必须有 NetworkPolicy（generate 规则）
5. 镜像必须已签名（cosign verify，供应链闭环）

## 对本项目

k8s-plugins/security/kyverno；策略文件随 GitOps 管理（策略也是 GitOps 对象）。
