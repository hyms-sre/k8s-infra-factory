# 多云策略

## 原则：抽象要有度

- **复用的是方法与 schema**（cluster.yaml、cloud-init、插件清单），不是强行做
  Terraform 抽象层（Terraform module 多云抽象的成本通常大于收益）
- 平台差异隔离在 `terraform/<平台>/` 内，live/ 环境组织跨平台复用
- 应用层（K8s 之上）天然多云：Gateway API/CNCF 插件/ArgoCD 均与平台无关

## 分层依赖与可移植性

| 层 | 可移植性 | 说明 |
|---|---|---|
| K8s 工作负载 | 高 | manifest/helm 无平台差异 |
| 存储/入口 | 中 | StorageClass/LoadBalancer 语义一致，实现不同 |
| 网络/计算 | 低 | terraform/<平台> 各自实现 |

## 未来扩展（Huawei Cloud 等）

新增平台 = 新增 `terraform/<平台>/`（按 vsphere 蓝本）+ live/<env>/<平台>/ 记录，
**不修改**现有平台层与插件层——这是"不要为了未来平台提前做复杂抽象"的具体含义。
