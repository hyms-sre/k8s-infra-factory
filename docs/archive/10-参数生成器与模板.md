## 1. terraform.py — 生成虚拟机参数

用命令行描述集群拓扑，一键产出 tfvars，避免手工复制时改漏 IP / 规格 / 版本。

```bash
./terraform.py --help                       # 全部参数
make generate GEN_ARGS="--masters 1 --workers 5 --cni calico --generate-password"
```

### 支持的配置维度

| 维度 | 参数 | 说明 |
|---|---|---|
| 主机名 | `--cluster-name` `--vm-name-prefix` `--date` | fqdn 前缀 / vSphere 显示名前缀 / 命名日期段 |
| IP 分配 | `--network` `--ip-start` `--default-gateway` `--nameservers` | 从 `--ip-start` 顺序分配，自动跳过网关/网络/广播地址 |
| 规格 | `--{master,worker,registry,gateway}-{cpu,mem,disk,data-disk}` | 留空则用 `locals.tf` 的 `role_defaults` |
| 凭据 | `--password` `--generate-password` `--enable-password-auth` `--ssh-key-file` `--ssh-key` | SSH 公钥可重复传；未指定时自动探测 `~/.ssh/id_ed25519.pub` |
| 网络插件 | `--cni cilium\|calico\|flannel\|none` | 见 §2 |
| 台数 | `--masters N` `--workers N` `--registry N` `--gateway N` `--extra role:count` | **不限台数**；`--extra` 可重复追加任意角色 |
| 复杂拓扑 | `--spec topology.json` | 逐台固定 IP / 混合规格；支持 JSON，YAML 需 PyYAML |
| 特性开关 | `--no-nerdctl` `--docker-ce` `--no-helm` `--k9s` `--no-bash-completion` `--no-motd` | 对应模板里的 `%{if ...}` |
| 镜像仓库 | `--harbor-host` `--harbor-ip` `--no-harbor` | 节点 certs.d 代理配置 |
| 输出 | `--output` `--dry-run` | `--dry-run` 只打印不落盘；覆盖前自动备份 `.bak` |

### 示例

```bash
# 1 控制面 + 5 worker + 1 registry，Calico，自动生成强口令
./terraform.py --masters 1 --workers 5 --registry 1 \
    --cni calico --generate-password \
    --ssh-key-file ~/.ssh/id_ed25519.pub \
    --output examples/kubernetes/terraform.tfvars

# 3 控制面 HA，起始 IP 从 .210 起
./terraform.py --masters 3 --workers 3 --registry 0 --ip-start 172.16.222.210 --dry-run

# 固定 IP / 混合规格
./terraform.py --spec examples/kubernetes/topology.example.json --dry-run
```

### 内建校验

- IP 冲突、越界（超出网段）、网络/广播地址占用
- 角色合法性（`control-plane` / `worker` / `registry` / `gateway`）
- 控制面数量为偶数时告警（etcd 建议奇数）
- `--spec` 与 `--masters/...` 互斥（避免语义冲突）
- SSH 公钥文件不存在 / 为空时直接报错

> 命名规范：`vm_name = <前缀>-<角色短名><序号>[后两段IP]-<日期>`，
> `fqdn = <集群名>-<角色短名>-<序号>`。若需与**既有**集群命名逐字一致，请用 `--spec` 精确指定。

## 2. 版本与组件目录（locals.tf）

三个目录表把"散落各处的版本号"收敛成单一入口：

| 目录 | 入口变量 | 作用 |
|---|---|---|
| `k8s_catalog` | `var.k8s_version` | 派生 apt 源 / sandbox(pause) 镜像 / crictl 版本 |
| `cni_catalog` | `var.cni_plugin` | 派生 pod_cidr / 镜像清单 / 安装方式 |
| `role_defaults` | `var.virtual_machines[*].role` | 派生未显式指定时的 CPU/内存/磁盘 |

| `k8s_version` | apt 源 | sandbox 镜像 | crictl |
|---|---|---|---|
| `v1.33` | `.../v1.33/deb/` | `pause:3.10` | `v1.33.0` |
| `v1.36` ★ | `.../v1.36/deb/` | `pause:3.10.1` | `v1.33.0` |
| `v1.37` | `.../v1.37/deb/` | `pause:3.11` | `v1.34.0` |

| `cni_plugin` | 版本 | pod_cidr | 说明 |
|---|---|---|---|
| `cilium` ★ | v1.17.0 | 10.244.0.0/16 | eBPF 数据面，需内核 5.10+ |
| `calico` | v3.30.3 | 10.244.0.0/16 | iptables/IPIP，NetworkPolicy 生态最全 |
| `flannel` | v0.26.1 | 10.244.0.0/16 | 最轻量，无 NetworkPolicy |
| `none` | — | — | 自行接入 CNI |

> ⚠️ 切换 CNI 会改变集群网络实现，运行中切换需重建网络，请谨慎。

## 3. userdata-v2.tftpl — 条件参数写法

模板用 Terraform 模板指令按开关裁剪：

```
%{ if nerdctl } ... %{ endif }            # 按开关决定是否执行
%{ for reg, proj in harbor_upstreams }    # 按上游列表展开
```

### 特性开关

| 开关 | 默认 | 作用 |
|---|---|---|
| `nerdctl` | ✅ | 安装 containerd 依赖（nerdctl 二进制走离线包分发） |
| `docker_ce` | ❌ | 从阿里云源安装 docker-ce 全家桶 |
| `helm` | ✅ | 预置 helm 补全目录 |
| `k9s` | ❌ | 预留（需分发离线二进制） |
| `bash_completion` | ✅ | bash-completion + kubectl/kubeadm 补全 + `k` 别名 |
| `motd` | ✅ | 写入 GZD Cloud 欢迎信息 |

### 镜像仓库配置（新增）

按 `local.harbor_upstreams` **动态生成**每个上游的 certs.d：

```toml
server = "https://docker.io"

[host."https://harbor.yjscloud.local/v2/dockerhub"]
  capabilities = ["pull", "resolve"]
  override_path = true
```

覆盖 6 个上游：`docker.io→dockerhub`、`quay.io→quay`、`ghcr.io→ghcr`、
`registry.k8s.io→k8s`、`gcr.io→gcr`、`mcr.microsoft.com→mcr`。

**同时修正了 containerd 的致命坑**：`config_path` 必须为单一路径
`/etc/containerd/certs.d`，多路径（冒号分隔）会让 CRI 静默忽略整个 certs.d
→ `crictl pull` 直连上游超时。详见 [docs/09](09-Harbor-HTTPS与代理缓存修复.md)。

### 其他

- 写入 `/etc/gzd-cluster.conf`（集群元信息），供阶段脚本读取
- 可选密码登录：`vm_password` + `enable_password_auth`（默认仅密钥，安全基线）
- 按 `role` 决定是否挂载 Longhorn 数据盘

## 4. GZD Cloud 欢迎信息

单一数据源：`files/motd/gzd-banner.txt`（cloud-init 与 Shell 脚本共用，避免漂移）。

```
  ____  _____ ____       ____  _       ___   _   _  ____
 / ___||__  /|  _ \     / ___|| |     / _ \ | | | ||  _ \
| |  _   / / | | | |   | |    | |    | | | || | | || | | |
| |_| | / /_ | |_| |   | |___ | |___ | |_| || |_| || |_| |
 \____|/____||____/     \____||_____| \___/  \___/ |____/
```

### 转义序列（关键）

`/etc/issue` 由 agetty 解析，以下必须是**字面反斜杠 + 字母**：

| 转义 | 渲染为 |
|---|---|
| `\n` | 主机名 |
| `\4` | IPv4 地址 |
| `\6` | IPv6 地址 |
| `\t` | 当前时间 |
| `\S` / `\r` / `\l` | 系统名 / 发行版 / tty |

> 本机 agetty 为 util-linux **2.39.3**，支持 `\4` / `\6`（2.28+ 引入）。
> 一旦被提前展开成真实换行/制表符，agetty 就拿不到转义了 ——
> 因此模板与脚本一律用**带引号的 heredoc**，禁用变量展开。

`/etc/motd` 不做转义解析，所以那里的缩进使用**真实制表符**（`printf '\t'`）。

### 安装位置

| 文件 | 作用 |
|---|---|
| `/etc/issue.d/10-gzd-banner.issue` | ASCII banner（banner 以 base64 传入，规避 YAML 缩进规则） |
| `/etc/issue.d/50-gzd-cloud.issue` | GZD Cloud 说明 + 转义序列 |
| `/etc/motd` | 登录后显示（真实制表符缩进） |
| `/etc/update-motd.d/00-gzd-cloud` | 动态 motd（`00-` 前缀使其排在 Ubuntu 自带项之前） |
| `gzd-motd.service` | 开机重建 `/run/motd.dynamic` |

> Ubuntu 的 `pam_motd` 读 `/run/motd.dynamic`，而 `/run` 重启即清空，且
> `/etc/pam.d/sshd` 里带了 `noupdate` —— 所以必须用 systemd 单元保证开机重建。
> 另外已停用 `50-motd-news`（登录时会联网抓 Canonical 新闻，受限网络下徒增延迟）。

### 应用到已有节点

```bash
make motd                                  # 全部 K8s 节点
MOTD_NODES="172.16.222.201" make motd      # 仅指定节点
```
