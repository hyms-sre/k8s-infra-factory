# 数据库 HA / 备份 / 恢复

## HA 形态对比

| 形态 | RTO | RPO | 复杂度 | 适用 |
|---|---|---|---|---|
| 单实例 + 备份 | 小时级 | 天/小时 | 低 | 开发/边缘 |
| 主从异步复制 | 分钟(切)+损尾部 | 秒 | 中 | 一般业务 |
| 同步复制 + 自动 failover (Operator) | 秒~十秒 | 0~亚秒 | 中高 | 生产关系库 |
| 多写集群 (Galera/RGW) | 秒 | 0 | 高 | 特殊场景 |

K8s 加成：Node 故障时 Operator 把 Pod 迁到健康节点重新拉起——**前提**是 PV 数据
可用（Longhorn 副本在其它节点）。

## 备份矩阵（每个库两条腿）

1. **存储快照**（Longhorn snapshot/backup）：整卷、快、恢复粗粒度
2. **逻辑/物理导出**（pg_dump、xtrabackup、ES snapshot）：细粒度、可跨版本

调度示例（CronJob + cnpg backup CR / es snapshot policy）+ 备份目标对象存储（MinIO）。

## 恢复演练（季度强制）

1. live/lab 起隔离 namespace
2. 恢复最近备份 → 应用指向 → 数据校验（行数/抽样比对）
3. 记录实际 RTO/RPO → 输入 docs/11-SRE 的 SLO 修订
4. 演练脚本入 Git（可重复执行）

## 事故清单（先于事故准备好）

- 主库失联：Operator 自动切主的观察点（Pod label/Service 指向）
- PV 丢失：Longhorn 卷从备份重建的步骤
- 集群整体丢失：velero/etcd 恢复路径（docs/07-存储/05 + docs/02-Kubernetes/07）
