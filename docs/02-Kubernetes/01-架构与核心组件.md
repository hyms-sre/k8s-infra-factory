# 架构与核心组件

## 总览

```
Control Plane (master)                      Worker 节点
┌─────────────────────────┐                ┌──────────────────┐
│ kube-apiserver          │◄── 唯一入口 ────│ kubelet          │
│ etcd        (状态存储)   │                │   ├─ Pod 生命周期 │
│ kube-scheduler (调度)    │                │   └─ 上报状态     │
│ kube-controller-manager │                │ containerd (CRI) │
│ cloud-controller-manager│                │ kube-proxy       │
└─────────────────────────┘                └──────────────────┘
```

## Control Plane 组件

- **kube-apiserver**：唯一入口，所有读写（人、组件、CI）都经过它；认证/鉴权/准入在这里发生
- **etcd**：分布式 KV 存储，保存集群全部状态。**最需要备份的组件**
  （奇数节点部署，raft 强一致）
- **kube-scheduler**：决定 Pod 落在哪个节点：过滤（资源/亲和/污点）→ 打分（均衡/亲和权重）
- **kube-controller-manager**：一组控制器的集合，各管一类对象的"实际状态向期望状态调和"
  （Deployment 副本数、Node 生命周期、Endpoint 维护…）

## 节点组件

- **kubelet**：每节点的"管家"， watch 分配到本机的 PodSpec，通过 CRI 让 runtime 拉镜像起容器，上报状态
- **Container Runtime (containerd)**：真正拉镜像/创建容器的组件，经 CRI 接口被 kubelet 驱动
  ——本项目 Cloud-Init 装的就是它（SystemdCgroup 必须为 true）
- **kube-proxy**：每节点维护 Service 的转发规则（iptables/IPVS）

## 对本项目的映射

- Cloud-Init：装 containerd + kubelet/kubeadm/kubectl（kubeadm-ready）
- kubeadm init：拉起 control plane 静态 Pod（apiserver/etcd/scheduler/cm 全是 static pod）
- kubeadm join：worker 加入（kubelet 拿 bootstrap token 证书后受控）
