# 安全 (RBAC / ServiceAccount / Secrets / Pod Security)

## RBAC

四种对象：Role/ClusterRole（规则集）+ RoleBinding/ClusterRoleBinding（授予给主体）。

```yaml
kind: ClusterRole
rules:
- apiGroups: [""], resources: [pods], verbs: [get, list]
---
kind: RoleBinding
subjects: [{kind: User, name: alice}]   # User/Group/ServiceAccount
roleRef: {kind: ClusterRole, name: viewer}
```

Role 是 namespace 级，ClusterRole 是集群级。原则：**最小权限**。

## ServiceAccount (SA)

Pod 的"身份"。默认挂 default SA；给 Pod 明确身份后可配 RBAC：

```yaml
spec: {serviceAccountName: my-app}
```

Token 获取：`kubectl -n ns create token <sa> --duration=8760h`
（Headlamp 等控制台登录即用此法）。

## Secrets

base64（**不是加密**）存放敏感数据，RBAC 控制读取：

```bash
kubectl create secret generic db-pass --from-literal=password=xxx
```

- 挂载为 env 或 volume；etcd 中未加密（可开 encryption at rest）
- 外部方案：Sealed Secrets / External Secrets / Vault（docs/06-安全）

## Pod Security

- 1.25+ 用 Pod Security Admission（namespace 打 label 强制 baseline/restricted）
- 关键容器实践：`runAsNonRoot: true`、`readOnlyRootFilesystem`、`allowPrivilegeEscalation: false`、
  最小 capabilities
- 策略类需求（校验/变更/生成）用 Kyverno/OPA → docs/06-安全/05
