# 本项目 Kubernetes 实践

本项目落地 K8s 的全链路，按执行顺序：

## 1. 节点就绪（Terraform + Cloud-Init）

```
cluster.yaml → generate.py → vm.tf → terraform apply
→ vSphere VM（固定 IP/主机名/规格）→ Cloud-Init → kubeadm-ready
```

节点已具备：containerd（SystemdCgroup/单路径 certs.d/pause 镜像）、
kubelet+kubeadm+kubectl（apt-mark hold）、内核参数、swap 关闭、helm/nerdctl/补全、
（cn）Harbor certs.d 镜像映射。

## 2. 集群引导（kubeadm，见 07-kubeadm实践.md）

init（--image-repository 与 pause_registry 对应）→ kubeconfig → join → Cilium CNI →
`kubectl get nodes` 全 Ready。

## 3. 平台组件（k8s-plugins/，推荐顺序）

| 顺序 | 组件 | 目的 |
|---|---|---|
| 1 | MetalLB | LoadBalancer IP（后续 Web 组件的前提） |
| 2 | Longhorn | 默认 StorageClass（数据盘已挂 /var/lib/longhorn） |
| 3 | Metrics Server | kubectl top / HPA |
| 4 | cert-manager | 插件间证书（Harbor/Ingress） |
| 5 | Gateway API + Envoy Gateway | L7 入口 |
| 6 | Prometheus + Grafana + Loki | 观测 |
| 7 | ArgoCD | GitOps |
| 8 | Headlamp | Web 控制台 |

## 4. 实测踩坑（详见 docs/99-参考/05-故障排查.md）

- containerd `config_path` 必须单一路径，否则 certs.d 被静默忽略
- MetalLB L2Advertisement 在 v0.14.x 是 v1beta1；CRD 建完清 ~/.kube/cache
- Envoy Gateway 大 CRD 用 `--server-side --force-conflicts`
- cn 拉镜像：预拉取+tag 或 Harbor proxy cache

## 5. 环境复现

同一套代码 + 不同 cluster.yaml 变体 = 不同环境（live/lab/vsphere/{default,cn}），
销毁重建（terraform destroy → generate → apply）即完整复位。
