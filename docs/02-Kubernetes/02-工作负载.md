# 工作负载

## Pod

最小调度单元：一个或多个共享网络/存储的容器组合。
- 每个 Pod 有独立 IP（pod_cidr 内），Pod 内容器 localhost 互通
- Pod 是易逝的——**不要直接管理 Pod**，用下面这些控制器

## Deployment（无状态应用）

```yaml
apiVersion: apps/v1
kind: Deployment
spec:
  replicas: 3
  selector: {matchLabels: {app: web}}
  template: {metadata: {labels: {app: web}}, spec: {containers: [{name: web, image: nginx:1.27}]}}
```

滚动更新（maxSurge/maxUnavailable）、回滚（rollout undo）、副本自愈。
**默认选择**——web/API/worker 一律 Deployment。

## StatefulSet（有状态应用）

稳定的网络标识（`<name>-0, -1, ...`）+ 稳定存储（volumeClaimTemplates，每副本独立 PVC）
+ 有序部署/伸缩。用于数据库、MQ、ES 等。配合 Headless Service（clusterIP: None）。

## DaemonSet（每节点一个）

日志采集（Promtail/Fluent Bit）、监控 agent（node-exporter）、CNI（Cilium）、
存储 agent（longhorn-manager）都是 DaemonSet。新节点加入自动部署——这就是
"节点只要加入集群就自动具备某能力"的机制。

## Job / CronJob

- Job：跑完即止（构建、迁移、备份脚本），`completions/parallelism/backoffLimit`
- CronJob：定时触发 Job（cron 语法），`concurrencyPolicy: Forbid|Replace|Allow`

## 排障速查

```bash
kubectl get pods -o wide                    # 状态/IP/节点
kubectl describe pod <p>                    # Events 是金矿
kubectl logs [-p] [-c 容器] <p>              # 日志 (-p 上次崩溃的)
kubectl exec -it <p> -- sh                  # 进容器
kubectl get deploy <d> -o yaml              # 看生效配置
```
