# 存储

## 核心对象

```
StorageClass (动态供给的"模板")
      ↓ PVC (用户的申请)
PV (实际的存储卷) ←── 静态: 管理员手工建; 动态: SC 自动建
      ↓
Pod (volume 挂载 PVC)
```

- **PV**：集群级存储资源（容量/访问模式/回收策略 Retain|Delete）
- **PVC**：命名空间的存储申请，与 PV 绑定
- **StorageClass**：定义"怎么动态创建 PV"（provisioner + 参数 + reclaimPolicy），
  可标记默认 SC
- **CSI**：存储厂商实现的标准接口；Longhorn/NFS provisioner 都是 CSI 驱动

## 访问模式

RWO（ReadWriteOnce，块存储典型）/ ROX / RWX（共享文件系统，如 NFS）。

## 本项目落地

1. 节点附加数据盘由 Cloud-Init 格式化挂载到 `/var/lib/longhorn`
2. k8s-plugins/storage/longhorn：DaemonSet 聚合各节点数据盘 → 动态 PV
   → 设为默认 StorageClass
3. NFS 方案见 k8s-plugins/storage/nfs（RWX 场景）

```bash
kubectl get sc,pvc,pv
kubectl patch storageclass longhorn -p '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
```
