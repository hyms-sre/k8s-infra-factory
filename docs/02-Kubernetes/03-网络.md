# 网络

## Service

Pod 易逝 → 用 Service（稳定 VIP + DNS 名）暴露一组 Pod（按 label 选择）：

| 类型 | 行为 |
|---|---|
| ClusterIP（默认） | 集群内虚拟 IP |
| NodePort | 每节点开端口 (30000-32767) |
| LoadBalancer | 接云 LB / **MetalLB**（本项目插件） |
| ExternalName | DNS CNAME 别名 |

```bash
kubectl expose deploy web --port=80
```

## DNS (CoreDNS)

集群内域名：`<svc>.<ns>.svc.cluster.local`；同 namespace 可短名。
Pod 的 /etc/resolv.conf 指向 kube-dns Service。排障：
`kubectl run tmp --rm -it --image=busybox -- nslookup <svc>`。

## CNI

容器网络接口插件，负责 Pod IP 分配与跨节点互通。**没有 CNI 节点永远 NotReady**。
本项目默认 Cilium（eBPF 数据面，需内核 5.10+），备选 calico/flannel；
安装是集群引导的一部分（docs/02-Kubernetes/07 与 09）。
`kubernetes.pod_cidr` 必须与 kubeadm init 的 --pod-network-cidr 一致。

## NetworkPolicy

L3/L4 级 Pod 间防火墙（默认全通，需显式定义 deny/allow）：

```yaml
kind: NetworkPolicy
spec:
  podSelector: {matchLabels: {app: db}}
  ingress:
  - from: [{podSelector: {matchLabels: {app: api}}}]
    ports: [{port: 5432}]
```

需要 CNI 支持（Cilium/Calico 支持，flannel 不支持）。

## Ingress / Gateway API

- **Ingress**：L7 入口规则（host/path → Service），需 Ingress Controller（ingress-nginx 等）
- **Gateway API**（新一代，本项目 k8s-plugins/networking/gateway-api）：
  GatewayClass / Gateway / HTTPRoute 三层角色分离，比 Ingress 的注解式扩展干净得多；
  数据面本项目用 Envoy Gateway

```yaml
kind: HTTPRoute
spec:
  parentRefs: [{name: lab-gw}]
  hostnames: ["app.example.com"]
  rules: [{matches: [{path: {value: /}}], backendRefs: [{name: web, port: 80}]}]
```
