# 调度与资源管理

## Requests / Limits

```yaml
resources:
  requests: {cpu: 100m, memory: 128Mi}   # 调度依据 (保证量)
  limits:   {cpu: 500m, memory: 256Mi}   # 运行上限
```

- cpu 单位 m（千分之一核）；memory 用 Mi/Gi
- 不设 limits：可无限制抢占节点资源（小环境常见做法，但 noisy neighbor 风险）
- 不设 requests：调度器无法做容量判断
- **节点资源 = Pod requests 总和 ≤ allocatable**——规划节点规格时按 requests 算

## Taints（节点）与 Tolerations（Pod）

污点是节点的"排斥标记"，容忍才能上去：

```bash
kubectl taint node node1 key=value:NoSchedule     # 打污点
kubectl taint node node1 key-                     # 去污点
```

master 默认带 `node-role.kubernetes.io/control-plane:NoSchedule`
→ 单 master 环境想让负载上控制面需手工去掉污点或加 toleration。

## Affinity（亲和/反亲和）

```yaml
affinity:
  nodeAffinity: {requiredDuringSchedulingIgnoredDuringExecution: {...}}   # 调到特定节点
  podAntiAffinity: {...}            # 副本打散到不同节点 (HA 关键)
```

topologyKey 常用 `kubernetes.io/hostname`（节点级）或 zone（可用区级，Toplogy 分布）。

## Topology Spread Constraints

比 podAntiAffinity 更细的"按拓扑域均匀分布"（maxSkew 控制不均衡度），
多副本高可用优先用它。
