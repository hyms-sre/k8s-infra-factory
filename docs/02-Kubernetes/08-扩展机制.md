# 扩展机制 (CRD / Operator / Admission / 多集群)

## CRD (Custom Resource Definition)

向集群注册新的资源类型：

```yaml
kind: CustomResourceDefinition
spec:
  group: metallb.io
  names: {kind: IPAddressPool, plural: ippaddresspools}
  scope: Namespaced
  versions: [{name: v1beta1, served: true, storage: true}]
```

之后就能 `kubectl get ippaddresspools`——K8s 把"声明式调和"能力开放给了任何领域。
本项目插件大量使用：MetalLB IPAddressPool、Gateway API 的 Gateway/HTTPRoute、
Longhorn Volume、cert-manager Certificate 全是 CRD。

## Operator

Operator = CRD + 自定义控制器：把领域运维知识编码成代码（部署/扩缩/备份/故障自愈）。

```bash
kubectl apply -f https://.../eck-operator.yaml   # ECK: 用 CR 管 ES 集群
kubectl apply -f es.yaml                          # Elasticsearch CR → operator 调和
```

判断要不要写/用 Operator：该软件是否有复杂的日常运维状态机（主从切换、扩缩容、备份）。
有 → 找现成 Operator；没有 → Deployment+脚本更简单。

## Admission (准入控制)

请求过 API Server 的两道闸：认证/鉴权之后、写入 etcd 之前。

- **Validating/Mutating Webhook**：外部 HTTP 服务校验/修改对象
- **Pod Security Admission**：内置的 Pod 安全基线
- **策略引擎**：Kyverno（K8s 原生 YAML 写策略）/ OPA Gatekeeper（Rego）
  ——本项目 k8s-plugins/security/

## 多集群

- 管理面：kubectl 多 context、ArgoCD/Flux 多集群注册（docs/05-GitOps）
- 网络互通：Submariner / 镜像同步
- 本项目路线：一套 terraform/vsphere 可重复生成多套集群（cluster.yaml 按 live/<env> 变体）

## 学习顺序建议

CRD（会读会写 YAML）→ 装一个现成 Operator 观察（ECK/Longhorn）→
Kyverno 写第一条策略 → Admission 原理。
